MM3 Character Record / Hit-Chance Research

Confirmed:
- Character record base (index 0, Sir Canegm): physical 0x2BF12
- Character record stride: 0x012F bytes
- Character record physical address:
  0x2BF12 + index * 0x012F

Confirmed address derivation from runtime code:
- DS = 0x2053
- base offset = 0xB9E2
- runtime offset = 0xB9E2 + index * 0x012F
- physical = DS * 0x10 + offset

Example index 0:
- 0x2053 * 0x10 + 0xB9E2 = 0x2BF12

Example index 5:
- offset = 0xB9E2 + 5 * 0x012F = 0xBFCD

Character record fields confirmed:
- +0x00: Name / character record start
- +0x1E: Accuracy
  physical for index 0: 0x2BF30
- +0x23: Level
  physical for index 0: 0x2BF35

Runtime code around caller 0x32057:
- mov al, [bx-0x132B]   -> loads character index
- mov ah, 0
- mov dx, 0x012F
- imul dx
- add ax, 0xB9E2
- push ax
- call far 0x0CEB:0x1D9B

Interpretation:
- The caller constructs a far pointer to the selected character record.
- The called routine 0x0CEB:0x1D9B receives that character-record pointer.

Hit-Chance Level Divisor / Class Dispatch
25.08.2026

Confirmed runtime path:

The routine reads the character class from the character record.

Relevant sequence:

    mov al, [bx+0x13]
    mov ah, 0x00
    mov bx, ax
    cmp bx, 0x09
    jnbe ...
    shl bx, 0x01
    jmp cs:[bx+0x1753]

Interpretation:
- Character record field +0x13 is the class ID.
- The class ID is loaded into BX.
- Valid class IDs are 0..9.
- BX is multiplied by 2 because the jump table contains 16-bit entries.
- The jump table selects a class-specific code path.

Confirmed class IDs:

    0 = Knight
    1 = Paladin
    2 = Archer
    3 = Cleric
    4 = Sorcerer
    5 = Robber
    6 = Ninja
    7 = Barbarian
    8 = Druid
    9 = Ranger

Observed class dispatch:

Knight:
    class ID = 0
    DI = 0x0001

Paladin:
    class ID = 1
    DI = 0x0002

Cleric:
    class ID = 3
    DI = 0x0003

Robber:
    class ID = 5
    DI = 0x0002

Barbarian:
    class ID = 7
    DI = 0x0001

Confirmed purpose of DI:

Later in the routine:

    xor dx, dx
    div di

DI is therefore the class-specific divisor used for the
level contribution to Hit Chance.

Current divisor table:

    Class       ID    Hit-Chance Level Divisor
    ------------------------------------------------
    Knight       0              1
    Paladin      1              2
    Archer       2              ?
    Cleric       3              3
    Sorcerer     4              ?
    Robber       5              2
    Ninja        6              ?
    Barbarian    7              1
    Druid        8              ?
    Ranger       9              ?

Current interpretation:

    levelContribution =
        level / classHitChanceDivisor

The division is integer division.

Examples:

    Knight:
        level / 1

    Paladin:
        level / 2

    Cleric:
        level / 3

    Robber:
        level / 2

    Barbarian:
        level / 1

This explains the previously observed Paladin behavior where
the level contribution increases only every two levels.
