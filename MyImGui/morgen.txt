Notiz für morgen – Execution Trace UI Umbau

Stand: 26.08.2026

Ziel

Die auseinandergezogenen Funktionen wieder in einem gemeinsamen
Execution-Trace-Hauptfenster zusammenführen.

Die einzelnen Analysewerkzeuge bleiben getrennte, kompakte Unterfenster,
damit sie nicht den ganzen Bildschirm einnehmen.

Gemeinsame Navigation

Die Navigation soll im besten Fall keinen sichtbaren Header/Tab haben.

Sie enthält die gemeinsamen Bedienelemente nur einmal: -
Target-Editfeld - Load - Save - Previous / Next - Anzeige des aktuell
ausgewählten Datensatzes / der Instruction

Beispiel: Target [0x……..] [Load] [Save] [<] Instruction x / y [>]

Die Navigation soll von allen Analyse-Unterfenstern gemeinsam genutzt
werden.

Analysefenster

Die sichtbaren Fensternamen müssen kurz bleiben, damit die Dock-Tabs
lesbar sind.

Exakt diese sichtbaren Namen verwenden: - Trace - Trans - Exec - MemWr

Trace: - Execution Trace - Runtime-History / Instruktionsverlauf

Trans: - Transition Recording - Transition-History

Exec: - Execution Capture - Einzelner Runtime-Snapshot - CS:IP -
Register - Stack

MemWr: - Memory Write Watch - Beobachtet eine Datenadresse - Später soll
zusätzlich die schreibende Instruktion erfasst werden

Architektur

Nicht alles neu programmieren.

Die bereits funktionierende Logik aus
InstructionTransitionTrackerNavigationWindow soll aufgeteilt und
wiederverwendet werden.

Navigation: - gemeinsames Target - Load / Save - Datensatznavigation

Trace / Trans / Exec / MemWr: - jeweils eigene Recorder-/Analyse-Logik -
jeweils eigene Ergebnisse - gemeinsame Navigation kann den jeweils
aktiven Datensatz bedienen

Execution Trace auszulagern war unpraktisch. Die Funktionen sollen
wieder in einem gemeinsamen Hauptbereich zusammengeführt werden.

Heutiger Memory-Write-Test

Memory Write funktioniert grundsätzlich.

Bestätigtes Test-Target: 0x2068E

Das ist der ausgewählte Party-Slot in MM3 (Byte).

Beim Wechsel des Party-Mitglieds hat der Memory-Write-Record-Button
korrekt automatisch gestoppt.

Damit ist bestätigt: - Memory-Write-Watch wird ausgelöst - Record-Button
funktioniert - automatisches Stoppen funktioniert

Wichtig: alter Datensatz

Nach dem Memory-Write-Treffer wurde weiterhin der alte
Transition-/Runtime-Datensatz angezeigt.

Das bedeutet NICHT, dass Memory Write falsch aufgenommen hat.

Memory Write besitzt momentan noch keine eigene Runtime-History bzw.
Capture-Struktur. Deshalb blieb in der gemeinsamen Anzeige der alte
Transition-Datensatz sichtbar.

Später: Memory Write soll beim Treffer auch die schreibende
x86-Instruktion erfassen.

Morgen zuerst

1.  UI-Struktur des Execution-Trace-Bereichs umbauen.
2.  Gemeinsame Navigation anlegen/integrieren.
3.  Target + Load + Save + Previous/Next in die Navigation verschieben.
4.  Die vier kurzen Unterfenster Trace, Trans, Exec und MemWr
    einrichten.
5.  Bestehende funktionierende Recorder-Logik wiederverwenden.
6.  Erst danach Memory Write um die schreibende Instruktion erweitern.

Nicht vorher wieder am Memory-Write-Hook experimentieren – der
grundlegende Write-Watch wurde heute mit 0x2068E erfolgreich bestätigt.
