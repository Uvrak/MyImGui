============================================================
BEKANNTE CURSOR-ADRESSE
============================================================

Lineare Speicheradresse:

0x87652

Bekanntes Verhalten:

- Die Adresse beeinflusst den MM3-Cursor.
- Sie enthält keinen einfachen An/Aus-Wert, sondern einen Pointer.
- Wird ein gültiger Wert/Pointer eingetragen, ändert sich der Cursor.
- Wird ein ungültiger Wert eingetragen, kann MM3 abstürzen.
- Deshalb nicht blind beliebige Werte auf 0x87652 schreiben.


============================================================
MEMORY WRITE TRACKING
============================================================

MemWr auf:

0x87652

Ergebnis:

NO HIT

Damit wurde beim untersuchten Cursorwechsel bisher kein direkter
Schreibzugriff auf 0x87652 gefunden.


============================================================
MEMORY READ TRACKING
============================================================

MemRd auf:

0x87652

Der Zugriff wird durch Space im Spiel ausgelöst.

Ergebnis:

HIT: 9B23:1D99
Read Address: 0x87652

Lineare Adresse der ausführenden Instruktion:

0x9CFC9

Instruktion:

0x9CFC9    8B 34    mov si,[si]

Damit ist bestätigt:

Die Instruktion bei 0x9CFC9 liest tatsächlich das Word an der
linearen Speicheradresse 0x87652.


============================================================
REGISTER VOR DEM READ
============================================================

Exec-Capture bei:

0x9CFC9

Register:

BX=0043
CX=0008
DX=0008

SI=0076
DI=0000

SP=FF84

ES=8B6D

WICHTIG:

DS=6173 darf hier NICHT einfach als Real-Mode-Adresse

    0x6173 << 4

interpretiert werden.

DOSBox verwendet für den tatsächlichen Speicherzugriff die
Segmentbasis (SegBase). Der MemRd-Hook misst die tatsächlich
verwendete lineare Adresse.

Diese wurde eindeutig als

0x87652

gemessen.


============================================================
ERGEBNIS DES READS
============================================================

Direkt nach

0x9CFC9    mov si,[si]

wurde ein Exec-Capture bei der nächsten Instruktion durchgeführt:

0x9CFCB

Register dort:

AX=0076
BX=0043
CX=0008
DX=0008

SI=1BC7
DI=0000
BP=23B9
SP=FF84

DS=6173
ES=8B6D
SS=2053

Damit:

Vor mov si,[si]:

SI = 0x0076

Nach mov si,[si]:

SI = 0x1BC7

Folgerung:

Beim untersuchten Vorgang enthält das Word an 0x87652 den Wert:

0x1BC7

Also:

0x87652 -> 0x1BC7

0x1BC7 wird anschließend als Pointer/Offset weiterverwendet.

============================================================
MEMRD-TRACKER ERWEITERUNGEN
============================================================

Der MemRd-Tracker wurde erweitert, sodass neben der
ausführenden Instruktionsadresse auch die tatsächliche
lineare Read-Adresse gespeichert und über IPC übertragen wird.

RuntimeInstruction besitzt dafür:

readAddress

Die MemRd-Anzeige zeigt jetzt beispielsweise:

Target: 0x87652
HIT: 9B23:1D99
Address: 0x87652

Damit können Instruktionsadresse und tatsächliche
Speicheradresse eindeutig voneinander unterschieden werden.


============================================================
NÄCHSTER SCHRITT
============================================================

Pointer 0x1BC7 weiterverfolgen.

Nächster Exec-Test:

Target:

0x9CFDA

Ablauf:

1. Exec auswählen.
2. Target 0x9CFDA setzen.
3. Record.
4. In MM3 Space drücken.
5. Register-Capture dokumentieren.

Besonders wichtig:

DS
SI
AX
BX
CX
DX
DI

Ziel:

Feststellen, wie die durch 0x87652 referenzierte Struktur ab
SI=0x1BC7 verarbeitet wird und ob es sich dabei direkt um
Cursor-Grafikdaten bzw. deren Beschreibung handelt.


============================================================
NICHT ERNEUT TESTEN
============================================================

Folgendes ist bereits bekannt und muss nicht erneut bewiesen werden:

- 0x87652 beeinflusst den Cursor.
- Ungültige Pointer an 0x87652 können MM3 abstürzen lassen.
- 0x87652 wird gelesen.
- Der Read erfolgt bei 0x9CFC9 / 9B23:1D99.
- Die Instruktion ist mov si,[si].
- Beim dokumentierten Test wird daraus SI=0x1BC7.
- Der Vorgang muss im Test mit Space ausgelöst werden.
